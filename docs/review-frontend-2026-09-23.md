## Замечания

### F1 · P1 — после Escape советник больше не открывается

Места: [static/app.js](../static/app.js), `closeModal` (375), обработчик Escape (421), `openAdvisor` (607).

Открыть «Объяснить», дождаться результата, нажать Escape, снова «Объяснить» или «Найти улучшение». `closeModal()` скрывает окно, но оставляет `state.advisorOpen=true`; `openAdvisor()` сразу возвращается. В Chromium подтверждено: оба повторных открытия оставляют `#modal` скрытым. До перезагрузки основной AI-разбор недоступен. Сбрасывать флаг при любом способе закрытия.

### F2 · Исправлено в 1d4cdcc — второй вопрос чата получал HTTP 422

Места: [static/app.js](../static/app.js), `sendChat` (582), особенно сериализация истории (587); [app.py](../app.py), `ChatMessage` (35).

Первый ответ сохранялся с полями `mode` и `checked`, затем вся история отправлялась без преобразования. Сервер разрешает только `role` и `content`. Изначально два последовательных вопроса в Chromium дали 200 и 422 (`extra_forbidden` для обоих полей). В `1d4cdcc` добавлено преобразование в `{role, content}`. Повторная проверка Chromium на чистой копии без ключа: оба запроса возвращают 200 / `unavailable`, ошибки схемы больше нет. Живой многошаговый диалог после этого изменения отдельно не вызывался.

### F3 · P2 — ответы советника смешиваются между сценариями

Места: [static/app.js](../static/app.js), `refreshResult` (513), `explainPlan` (546), `findImprovements` (560), `sendChat` (582).

При пересчёте полного плана B сохраняется старый `state.result=A`. Поздний ответ объяснения A успевает пройти проверку `scenario_key`, затем расчёт B меняет Score и оставляет объяснение/кандидатов A. Чат добавляет ответ без проверки сценария вообще. Управляемые задержки при выполнении настоящих функций через Node VM воспроизвели `result=B`, `explanation=A`, `candidates=A`, а также ответ чата A в очищенной истории B.

Для всех запросов советника проверять поколение `state.gen` перед записью ответа, ошибки и флагов загрузки. Объяснение и рекомендации должны относиться к тому же набору, что и видимый Score.

### F4 · P2 — закрытый советник сам открывается после ответа

Место: [static/app.js](../static/app.js), конец `explainPlan` (557).

Запустить объяснение, закрыть окно крестиком, открыть настройки до ответа. По завершении запроса `openAdvisor()` заменяет открытые настройки советником. Воспроизведено Node VM. Завершение запроса должно обновлять данные, а решение об открытии окна оставаться за пользователем.

### F5 · P2 — длинные окна правил и выбора меры не прокручиваются

Место: [static/app.css](../static/app.css), `.dlg` (325, 466).

Новый `overflow:hidden` перекрывает прежний `overflow:auto`, сохраняя `max-height:90vh`. В Chromium при 390×844 окно правил имеет видимую высоту 758 px и содержимое 1230 px. Автофокус кнопки прокручивает его вниз на 472 px, заголовок уходит выше экрана; прокрутка колёсиком вверх ничего не меняет. При 1366×768 содержимое также больше окна (925 против 689 px). Восстановить прокрутку содержимого. У нового советника отдельный прокручиваемый контейнер, это замечание относится к остальным окнам.

### F6 · P2 — бюджет выходит за правую границу телефона

Место: [static/app.css](../static/app.css), минимальные ширины (54, 59), медиазапрос (357), позднее переопределение `.top` (399).

В Chromium на ширине 390 px ширина документа 570 px, блок бюджета занимает x=310…570. Две колонки с `min-width:260px` не помещаются. На узком экране переносить блоки в одну колонку или снимать минимальные ширины.

### F7 · P2 — сбой поиска улучшений выдаётся за отсутствие улучшений

Место: [static/app.js](../static/app.js), `findImprovements`, ветка `catch`.

После успешного расчёта примера заблокировать `/api/improvements` и нажать поиск. Ошибка превращается в `candidates=[]`; интерфейс сообщает «Улучшений … не найдено», хотя для примера есть три кандидата. Ошибке сети необходимо отдельное состояние и повтор запроса.

### F8 · P2 — демонстрация патруля представлена как LIVE

Место: [static/patrol.js](../static/patrol.js), `EVENTS`, `openCamera`, строки 21, 103–108.

Камера — статичный JPG, события заранее записаны и повторяются таймером, телеметрия и уверенность фиксированы. Надписи `LIVE`, `RTSP`, «передано в службу» создают впечатление работающей интеграции, которой в коде нет. README теперь раскрывает демонстрационный характер; такая же пометка нужна непосредственно в окне. Изображения, по подтверждению пользователя, сгенерированы командой в Nano Banana Pro.

## Что работает

Клиент запрещает превышение бюджета, повторы, третью меру направления и несовместимости; итог считает сервер. В Chromium контрольный набор дал 56,54, объяснение загрузилось в `live` и `template`, применение `c1` дало 57,21. Ответ расчёта защищён поколением запросов. Тексты чата и объяснения экранируются. Mock-данные валидного сценария совпадают с движком. Синтаксическая проверка JavaScript проходит.

Часть воспроизведений использует реальные HTTP-запросы и Chromium, гонки — настоящие функции с управляемыми ответами в Node VM. Это не полный автоматический браузерный регрессионный набор.
