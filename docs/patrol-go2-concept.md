# Задача для фронтенда: блок «Патруль Go2» во вкладке «Безопасность»

Дата: 23.09.2026, 17:00. Решение Каната. Исполнитель: Алибек (`static/`), бэкенд не меняется. Срок: рабочая версия в `main` до 17:35, иначе блок не сдаём и оставляем в roadmap. Формула Score, эффекты мер, датасет и маршруты API не трогаем.

## Суть

Показать в симуляторе, каким станет раздел «безопасность» в реальном городе: по районам ходит патрульный робот-собака Unitree Go2 (реальный проект команды Astana Dynamics для МВД), он стримит камеру и его ИИ-агент постоянно комментирует, что видит: дефекты городской среды и ситуации, каждая привязана к району и к показателю симулятора. Это **концепт с демонстрационными данными**: события и «стрим» имитируются на фронтенде, к живому роботу ничего не подключается. Если жюри спросит — отвечаем «концепт на реальной платформе: стрим, детекция и патруль по точкам у робота уже работают, привязка событий к симулятору — следующий шаг».

## Что увидит пользователь

1. **Во вкладке «Безопасность»** (рядом с мерами M10, M11) — карточка «Патруль Go2 · Astana Dynamics»: фото/иконка робота, статус «на маршруте», район, который он сейчас проходит, кнопка «Открыть камеру».
2. **На условной схеме районов** — маркер робота, который медленно движется по маршруту через районы (SVG-анимация по точкам, как в реальном дашборде робота: точки `{x, y, θ}`, следующая точка после «прибытия»). Клик по маркеру = та же кнопка «Открыть камеру».
3. **Панель камеры** (модальное окно или правая колонка): область «видео» с оверлеем как у настоящего потока — `Go2 · RTSP H.264 · 640×480 · 15 fps · ЦОУ`, время, район; внутри — либо зацикленная запись/GIF с робота, если есть, либо фото с рамками детекций (имитация YOLO: рамки `person 0.87`, `car 0.91`). Под видео — **лента комментариев агента**, которая обновляется каждые несколько секунд из заранее написанного сценария (см. ниже), новые строки появляются сверху с временем и цветом по важности.
4. **Связь с симулятором (без изменения Score):** у каждого события — метка показателя: `B1` безопасность улиц, `B2` дорожное движение, `E2` воздух, `C1` ЖКХ. Внизу карточки — счётчик «сигналов за смену» по районам и подпись: «В рабочей версии эти сигналы обновляют показатели районов между сессиями симулятора. Сейчас — демонстрационные данные».
5. **Мелкая деталь, которая продаёт идею:** в объяснении советника ничего не менять, но в панели патруля показать строку «Сегодня больше всего сигналов: Нура (B1) — совпадает со слабейшим районом плана». Это чистый текст на основе демонстрационного счётчика, к расчёту не относится.

## Сценарий событий (демонстрационные данные, писать в `static/patrol_events.json` или прямо в JS)

Поля: `time`, `district_id`, `type`, `severity` (`info` / `warning` / `critical`), `indicator` (`B1`/`B2`/`E2`/`C1`), `text` (комментарий агента), `detections` (список классов с уверенностью для рамок).

Примеры, 12–15 штук на цикл, порядок перемешать по районам:

- `critical` `C1` Нура — «Открытый канализационный люк на проезжей части, ограждения нет. Передано в диспетчерскую ЖКХ.»
- `warning` `B1` Нура — «Электрощиток вскрыт, дверца снята. Риск для детей, рядом школа.»
- `warning` `B2` Алматы — «Яма на дороге глубиной ~15 см в правой полосе, машины объезжают через встречную.»
- `info` `B2` Есиль — «Пешеходный переход у школы: светофор работает, поток 40 чел./10 мин.»
- `critical` `E2` Сарыарка — «Газоанализатор: превышение CH₄ у частного сектора. Отправлено в аварийную службу.»
- `warning` `E2` Сарыарка — «Дым от печного отопления, видимость снижена.»
- `warning` `B1` Есиль — «Скопление 60+ человек у здания акимата, обстановка спокойная. Наблюдаю.»
- `critical` `B1` Байконур — «Ребёнок 6–8 лет один, плачет, взрослых рядом нет. Оператор уведомлён, робот остаётся рядом.»
- `info` `B1` Алматы — «Освещение на участке маршрута: 3 из 12 фонарей не горят.»
- `warning` `C1` Алматы — «Оборванный провод на опоре, искрение не наблюдается. Передано энергетикам.»
- `info` `B2` Байконур — «Разрушенный бордюр у остановки, помеха для колясок.»
- `warning` `B1` Есиль — «Совпадение с ориентировкой дежурной части (демо). Передано оператору, робот не вмешивается.»

Формулировки — от первого лица агента, коротко, с действием «передано / уведомлён / наблюдаю». Без имён, лиц и персональных данных.

## Что реально у робота (можно писать в интерфейсе как факт)

Unitree Go2, Jetson Orin NX; видеопоток H.264 640×480@15 fps по RTSP в ЦОУ; детекция YOLO11n (TensorRT, 80 классов COCO) с трекингом; патруль по точкам маршрута с порогом прибытия 1,5 м; журнал событий оператора с фильтрами. Источник: репозиторий команды `go2-mvd-system`. Чего пока нет (в интерфейсе не утверждать как готовое): классов «люк/щиток/яма/дым», газоанализатора, привязки событий к районам, распознавания лиц.

## Ограничения исполнения

- Только `static/`: `index.html`, `app.js`, `app.css`, `img/`, при необходимости `static/patrol_events.json`. Никаких новых зависимостей и CDN, никаких внешних запросов, никаких изменений в `engine/`, `app.py`, `data/`, тестах. README дополняет Claude.
- Работающая страница важнее блока: строить как изолированный модуль (свой контейнер, свои функции, свой CSS-префикс `.patrol-`), чтобы при ошибке в нём основной сценарий (расчёт, объяснение, замены, ключ, диалог) не ломался. Анимация — CSS/`requestAnimationFrame`, без тяжёлых картинок (фото робота ≤ 300 КБ).
- Подпись «Концепт · демонстрационные данные» на карточке — маленькая, но есть.
- Коммит отдельный: `feat: концепт патруля Go2 во вкладке «Безопасность» (демо-данные)`; перед push — `git pull` (fetch + merge, без rebase). Готовность: страница открывается, основной сценарий работает как раньше, маркер движется, камера открывается, лента идёт по кругу, все 60 тестов проходят.
