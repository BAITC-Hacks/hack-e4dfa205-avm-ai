# Опыт робота-собаки (Go2, МВД) и раздел «безопасность» симулятора: оценка полезности

Дата: 23.09.2026, 16:40. Автор: Claude по поручению Каната. Статус: **предложение, не согласовано для реализации**. Официальная формула Score, эффекты мер и датасет не меняются.

Источник: локальный снимок репозитория `github.com/Kanat06/go2-mvd-system` (BotBrain-форк для патрульного робота Go2, ROS2 Humble, дашборд Next.js). Изучались камеры и видеопотоки, детекция, патрулирование, события, интерфейс оператора. Служебные адреса, серийники и ключи из того репозитория сюда не переносятся.

## Что там реально есть и чего нет

| Есть (рабочий код) | Нет |
|---|---|
| Видеопоток: RealSense → GStreamer H.264 640×480@15, ~4 Мбит/с → mediamtx → RTSP для ЦОУ (`botbrain_ws/patches/ros2_rtsp_bridge.py`, `mediamtx.yml`); watchdog камеры (`system_etc/camera_watchdog.sh`) | Данных об инцидентах: ни логов, ни датасетов, ни примеров событий |
| Детекция: YOLO11n (80 классов COCO), TensorRT на Jetson Orin NX, трекинг BoT-SORT; выход JSON `{"detections_num","detected_objects":[{"object","confidence","track_id"}]}` (`botbrain_ws/src/bot_yolo/bot_yolo/yolo_node.py`) | Правил «детекция → тревога», уровней важности, геозон, классов «ДТП», «драка», «нарушение ПДД» |
| Патруль: оператор задаёт точки `{x, y, theta}` на карте, робот проходит их по очереди, порог прибытия 1,5 м (`frontend/src/components/map-view-nav2.tsx`); модель `missions`/`waypoints` | Гео-привязки к районам города, патруля по расписанию, истории детекций (нода-загрузчик и таблица `yolo_data` отсутствуют) |
| UI оператора: журнал событий с фильтром по типу, статистикой, цветом/иконкой на тип и выгрузкой CSV (`frontend/src/app/audit/page.tsx`); корзины уверенности ≥0,9 / 0,7–0,9 / <0,7 (`components/yolo-filter-bar.tsx`); enum `EventType` = auth, robot, command, system, data, mission, navigation, audio, camera, safety, export (`utils/audit-logger.ts`) | Это журнал действий оператора и робота, а не уличных инцидентов |

Вывод: **интегрировать робота в симулятор сегодня не нужно и нечем** — данных нет, а любые «события безопасности» пришлось бы синтезировать. Ценность опыта — в аргументации применимости и потенциала (критерии «ценность и применимость» 15 и «потенциал развития» 10) и в одном небольшом слое визуализации, если на него будет время после сдачи.

## Вариант 1 (рекомендую сейчас): «Откуда возьмутся реальные B1/B2» — текст в README и слайд, без кода

- **Что увидит пользователь/жюри:** абзац README «Путь к реальным данным» и один слайд: показатели B1 «безопасность улиц» и B2 «безопасность дорожного движения» в реальном внедрении могут питаться потоком с патрульных камер: стационарные камеры Safe City (проект Astana Innovations, 13 000 камер) и мобильная камера робота, который отдаёт H.264 по RTSP в ЦОУ и считает объекты классов COCO (`person` → пешеходная активность и освещённость для B1; `car`, `bus`, `truck`, `bicycle`, `traffic light`, `stop sign` → трафик и переходы для B2). Пример реального формата детекции — из `yolo_node.py`.
- **Связь с ТЗ:** критерии «ценность и применимость» и «потенциал развития»; мера M10 «освещение и камеры (расширение Safe City)» получает конкретную, проверенную командой техническую основу. Формула и эффекты не меняются.
- **Данные:** не нужны; используются только параметры, подтверждённые кодом (разрешение, битрейт, классы, порог 1,5 м), с оговоркой «инциденты и статистика в проекте робота не собирались».
- **Время:** 10 минут (Claude, README + тезис слайда). **Алибеку:** ничего.
- **Риск:** нулевой для сдачи; честность обеспечивается формулировками «может питаться», «в текущем прототипе данных нет».

## Вариант 2 (после хакатона или только при свободном фронтенде): «Условный журнал событий безопасности по районам»

- **Что увидит пользователь:** в карточке района вкладка «События безопасности (условно)»: список условных типов событий (освещение, ДТП, происшествие на улице, обращение) с ожидаемой частотой «до → после», выведенной детерминированно из B1/B2 до и после мер, с подписью «условная иллюстрация, не входит в Score». Паттерн интерфейса — журнал с фильтром по типу, цветом на тип и статистикой (как `audit/page.tsx`), корзины частоты как корзины уверенности в `yolo-filter-bar.tsx`.
- **Связь с ТЗ:** опциональный пункт «визуализация изменений показателей районов»; объяснение последствий становится нагляднее.
- **Данные и допущения:** реальных данных нет; частота = функция от показателя (например, линейно от (100 − B)), источник и допущение подписываются, результаты не смешиваются с официальным Score. Новый маршрут не обязателен: всё считается из `district_results` в браузере.
- **Время:** бэкенд 0–20 мин (при желании отдельный `GET /api/safety-events?…` с генератором), фронтенд 30–40 мин. **Алибеку:** отдельная вкладка и таблица; после 17:00 новые функции запрещены, поэтому сегодня — только если основной сценарий уже закрыт и остаётся время, иначе в «потенциал развития».
- **Риск:** средний — можно принять за фабрикацию данных, если подпись неочевидна; без фронтенда бессмысленно.

## Не предлагаю

- Подключать реальные камеры, RTSP, YOLO или Supabase к симулятору: это не помогает задаче, требует инфраструктуры и переносит служебные данные.
- Вводить «уровни угрозы», «спасённые жизни» или иные эффекты, которых модель ТЗ не считает.

## Замечание по безопасности репозитория робота

В снимке `go2-mvd-system` файл `.env` попал в git, а в `README_RESTORE.md`, `system_etc/*`, `patches/ros2_rtsp_bridge.py`, `go2_pkg/config/camera_config.yaml` есть внутренние адреса, MAC и серийники. К хакатону это отношения не имеет, но стоит убрать из истории и перевыпустить секреты после хакатона.
