## А. Понимание задачи

**Обязательно создать [ТЗ]:** единый бюджет 100 для всех; ровно 5 решений по 14 мерам пяти направлений; автоматический контроль бюджета; расчёт Astana Quality of Life Score по формуле ТЗ; AI-анализ решений; объяснение сильных сторон, рисков и последствий. Опционально: сравнение результатов, визуализация районов, AI-рекомендации, события-шоки, автопрезентация.

**Пользователь [ТЗ]:** городской управленец, аналитик, пользователь симулятора. Для демо это член жюри, который сам собирает план и хочет понять, почему Score такой.

**Завершённый сценарий:** открыл страницу → видит базу 52,56 и два критических показателя в Нуре → выбрал 5 мер с районами → система остановила перерасход или конфликт словами → получил Score, дельту к базе, три слагаемых прироста, показатели районов до/после → нажал «Объяснить» → получил разбор со ссылками на факты → нажал «Найти улучшение» → применил проверенную альтернативу → сравнил.

**Что проверят эксперты [ТЗ, AGENTS.md]:** запуск строго по README на чистой машине без нашего участия; пять критериев проверки (одинаковый старт, запрет перерасхода, влияние решений, понятное объяснение компромиссов, смена набора меняет Score); шесть must-have. Баллы техотбора: соответствие и работоспособность 25, техническая реализация 25, README и воспроизводимость 25, ценность 15, потенциал и оригинальность 10. Demo Day: ценность 25, сценарий 20, масштабирование 20, презентация 20, инновационность 15.

**Неоднозначности и как решены:**

| Вопрос | Решение | Основание |
|---|---|---|
| «5 решений по 5 направлениям» или «не более 2 из направления» | Ровно 5 решений, ≤2 на направление, минимум 3 направления затронуты, охват всех пяти не требуется | Правило 5 приложения к ТЗ; официальный пример 2/1/1/1 |
| Что такое «AI-анализ» без ключа | Режим `fallback`/`template`: объяснение собрано программой из тех же фактов, честно помечено. Живой режим — с ключом OpenAI | Требование проверки без личных аккаунтов |
| Вклад одной меры в Score | Не выдаём сумму вкладов за разложение: показываем эффекты меры на показатели и три слагаемых ΔScore (среднее, слабейший район, снятый штраф), которые в сумме дают дельту точно | Нелинейность min(D) и порога 40 |
| Явный `district_id: null` у городской меры | Принимается как «район не указан» | Удобство фронтенда, ТЗ не запрещает |

## Г. Продукт и интерфейс (зона Алибека, `static/`, по `docs/akim-spec.md` §9)

- **Один экран, три колонки:** каталог мер по вкладкам направлений (карточка: цена, район/город, лаг, эффекты) → центр: условная схема пяти районов, Score крупно, дельта к базе, три слагаемых, показатели до/после → справа «Мой план», «Найти улучшение», «Объяснить», A/B.
- **Ограничения и ошибки:** нарушение объясняется словами до отправки и повторно проверяется сервером; ошибки приходят с `decision_indexes` для подсветки.
- **Объяснение:** резюме, сильные стороны, риски, альтернативы с кнопкой «Применить» (набор берётся из расчёта, не из текста). Пометка режима: «AI (gpt-4o-mini)» или «AI недоступен, показано вычисленное объяснение».
- **Сравнение:** A/B в localStorage; при варианте 2 — ранг плана и «лучший план даёт X, чтобы прийти к нему: убрать…, добавить…».
- **Доступность (минимум, дёшево):** все действия с клавиатуры (Tab/Enter/Space), фокус виден, цвет всегда с числом или подписью, контраст ≥4.5:1, `aria-label` у карточек, размер целей ≥40 px. **[гипотеза]** это оценят как ценность и потенциал.
- **Визуализации, которые помогают:** столбики D по районам до/после; три слагаемых ΔScore; подсветка критических ячеек. Карта не нужна — районы условные, подпись «условная схема».

### AI-ресурсы и интеграция

**Что выдано [Канат, страница хакатона]:** ChatGPT & Codex Pro 5x на месяц; $50 OpenAI API credits; $50 NVIDIA API tokens; активация до 25.09.2026. Активация ≠ срок использования кредита: срок жизни кредита проверить в кабинете OpenAI (Billing) после активации **[не проверено]**. Codex/ChatGPT — инструмент разработки (Алибек уже использует Codex для ревью), в приложение не входит. Код активации в приложение не вставляется; нужен именно API-ключ, созданный в кабинете.

**Выбор провайдера:**

| | OpenAI `gpt-4o-mini` | NVIDIA API Catalog (`integrate.api.nvidia.com/v1`, Llama/Nemotron) | Оба |
|---|---|---|---|
| Русский язык | уверенно | зависит от модели, не проверено сегодня | — |
| JSON-режим / структурный ответ | есть (`response_format`) | OpenAI-совместимый SDK, поддержка JSON-режима зависит от модели **[гипотеза]** | — |
| Стоимость объяснения | ≈3,5K токенов вход + 0,6K выход ≈ $0,001 по публичному прайсу **[проверить]**; $50 — десятки тысяч запросов | кредиты в токенах, объём не проверен | — |
| Готовность кода | готов, тесты есть | смена `base_url` + ключ, 5 минут, но проверка качества ответов не проведена | усложняет README и проверку |

**Решение:** OpenAI `gpt-4o-mini` — единственный провайдер в этой версии. NVIDIA — как запасной провайдер через те же `OPENAI_BASE_URL`/`OPENAI_MODEL` **[потом]**, только после проверки качества русского JSON-ответа. GPU не нужен: табличная модель считается за миллисекунды, полный перебор 694 395 планов — 25 секунд на CPU один раз, результат в репо.

**Роль модели:** объяснение фактов (готово); комментарий к альтернативам (готово); диалог по фактам и топу планов (задача 12, если ключ); перевод запроса в набор мер с проверкой валидатором **[потом]**.

**Поток:** решения → `evaluate` → `find_improvements` → `build_facts` → модели уходят только `{id, kind, text}` фактов и `candidate_ids` → ответ JSON → проверка схемы, `fact_ids`, `candidate_id`, чисел (допуск 0,051 к числам из фактов) → `live`, иначе `fallback`. Кэш 100 ответов по ключу сценария, таймаут `LLM_TIMEOUT_S=15`, без повторов.

**Порядок подключения:** активировать кредит → создать ключ в кабинете → записать локально в `.env` строкой `OPENAI_API_KEY=…` (файл в `.gitignore`) → `python -c` из плана задачи 7, шаг 5 → ожидание `live gpt-4o-mini None`. Экспертам: ключ передаётся отдельно от репозитория; с задачей 12 ключ можно ввести в интерфейсе (заголовок `X-OpenAI-Key`, сервер не хранит) — проверка без нашего аккаунта.

**Критерии проверки:** `POST /api/explain` с ключом → `mode: live`, все `fact_ids` существуют, числа совпадают с фактами; без ключа → `fallback` и тот же сценарий проходит; тест `test_no_key_is_fallback_and_never_calls_model` гарантирует, что без ключа модель не вызывается.
