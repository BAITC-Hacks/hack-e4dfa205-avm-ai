## Замечания

### B1 · P2 — ограничение POST проверяется после чтения всего тела

Место: [app.py](../app.py), `BodyLimitMiddleware.dispatch`, строка 52.

`await request.body()` сначала сохраняет весь поток в памяти, затем проверяется лимит 16 KiB. На запрос с тремя чанками по 16 385 байт middleware прочитал все 49 155 байт до ответа 413. Большое тело занимает память вне зависимости от заявленного лимита.

Нужно прекращать чтение при превышении лимита, считая размер каждого чанка. `Content-Length` годится для раннего отказа, но не заменяет ограничение фактически прочитанных байтов.

### B2 · P2 — пустой ответ модели ломает контракт чата

Место: [engine/explain.py](../engine/explain.py), `chat`, строки 274–284 после изменения промптов.

Обработка исключений охватывает вызов провайдера, но не обработку его ответа. Подмена `chat_model=lambda *args: (None, 'fake')` при валидном сценарии и фиктивном заголовке ключа даёт HTTP 500: `_numbers_ok` ожидает строку. Для `''` и `'   '` возвращается `mode=live`, пустой `reply`, `numbers_checked=true`.

Проверять тип и непустоту текста внутри защищённого блока; некорректный ответ возвращать как понятную ошибку модели. Для воспроизведения использован TestClient, внешние запросы не нужны.

### B3 · Исправлено в e6387fc — тест терминального демо мог использовать настоящий ключ

Места: [tests/test_demo.py](../tests/test_demo.py), `test_demo_runs_offline_and_prints_key_numbers`; [scripts/demo.py](../scripts/demo.py), начало `main`.

Тест удаляет `OPENAI_API_KEY` из окружения, затем `main()` вызывает `load_dotenv(ROOT / '.env')`. Если разработчик сохранил ключ в `.env`, он загружается заново: тест может обратиться к платной модели, ждать сеть и получить `live` вместо ожидаемого `template`. В чистой копии без `.env` это не проявляется.

Безопасная подмена загрузчика и провайдера подтвердила попытку обращения к модели, которую fallback скрывал от теста. В `e6387fc` загрузка `.env` внутри теста отключена; итоговый чистый прогон проходит. Надпись «без сети» для самого `demo.py` верна только при отсутствии ключа. README уточнён.

## Ограничения оценки

Проверка чисел LLM лексическая. На контрольном наборе резюме `Score 100` может пройти из-за разрешённых констант, а `Score 1e100` — из-за разбора чисел регулярным выражением. Следовательно, `numbers_checked=true` не доказывает правильность Score в тексте. Расчётное поле API остаётся надёжным источником числа. Это уже оговорено README; семантический валидатор здесь не реализован.

`OPENAI_BASE_URL` проверен тестом настройки SDK; это не подтверждение совместимости всех методов API с любым провайдером. Квантили дают приближённый процентиль, а не точное место каждого набора. Реальную нагрузочную проверку и полноценный аудит безопасности этот проход не заменяет.
