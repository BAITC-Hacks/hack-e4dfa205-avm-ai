# Аким на 5 часов: AI-симулятор управления городом

Команда AVM AI, хакатон HackAlem AI, 23.09.2026. Задача 12, спец-трек Astana Innovations. Условия задачи: [docs/tracks/12-akim-tz.md](docs/tracks/12-akim-tz.md).

## Описание и назначение

Пользователь в роли акима получает бюджет 100 условных единиц и выбирает ровно пять городских мер из каталога 14 по пяти направлениям: транспорт, экология, соцсфера, безопасность, сервисы. Симулятор считает Astana Quality of Life Score по формуле из ТЗ, показывает, как изменились пять районов, находит проверяемое улучшение заменой одной меры и даёт AI-объяснение результата: сильные стороны, риски, компромиссы.

Модель учебная: районы, показатели и эффекты мер заданы условиями задачи и не являются данными о реальном бюджете Астаны.

Назначение: инструмент для обучения и обсуждения городского бюджета, где видно не только итоговую цифру, но и почему она такая, что стало со слабейшим районом и чем пришлось пожертвовать.

## Архитектура

```
Браузер (static/)  ──HTTP JSON──▶  FastAPI (app.py)
                                      │
                                      ├─ engine/validator.py   правила набора
                                      ├─ engine/scoring.py     формула Score, разложение прироста
                                      ├─ engine/advisor.py     поиск улучшения заменой одной меры
                                      ├─ engine/facts.py       факты для объяснения, резервный текст
                                      └─ engine/explain.py     OpenAI: объяснение по фактам, проверка ответа
                                            │
                                      data/city.json          районы, меры, правила из ТЗ
```

Расчёт детерминирован и выполняется на сервере по данным из `data/city.json`. Браузер отправляет только идентификаторы мер и районов. LLM получает уже посчитанные числа и объясняет их, сам ничего не считает. Без ключа модели приложение работает полностью, объяснение собирается из тех же фактов шаблоном и помечается как резервный режим.

Подробная спецификация: [docs/akim-spec.md](docs/akim-spec.md).


## Переменные окружения

См. [.env.example](.env.example). Скопировать в `.env` и заполнить при необходимости.

| Переменная | Назначение |
|---|---|
| `OPENAI_API_KEY` | Ключ OpenAI для живого AI-объяснения. Пусто: резервный режим, расчёт работает полностью |
| `OPENAI_MODEL` | Модель, по умолчанию `gpt-4o-mini` |
| `LLM_TIMEOUT_S` | Таймаут запроса к модели в секундах, по умолчанию 15 |

Ключ для проверки живого AI-режима передаётся организаторам при сдаче отдельно от репозитория.

## Проверка основного сценария

Заполняется по мере реализации. Планируемый сценарий:

1. Открыть http://localhost:8000. Видна база: Score 52.56, два критических показателя в Нуре.
2. Нажать «Пример из ТЗ»: набор M7 Нура, M8 Нура, M10 Нура, M12 город, M5 Сарыарка. Стоимость 95, Score 56.54, критических показателей нет.
3. Попробовать добавить шестую меру или превысить бюджет: интерфейс объясняет причину и не применяет.
4. Нажать «Объяснить»: появляется разбор от модели или резервное объяснение с пометкой.
5. Нажать «Найти улучшение»: до трёх проверенных альтернатив с дельтой Score, кнопка «Применить».
