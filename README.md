# Аким на 5 часов: AI-симулятор управления городом

Команда AVM AI, хакатон HackAlem AI, 23.09.2026. Задача 12, спец-трек Astana Innovations. Условия задачи: [docs/tracks/12-akim-tz.md](docs/tracks/12-akim-tz.md).

## Описание и назначение

Пользователь в роли акима получает бюджет 100 условных единиц и выбирает ровно пять городских мер из каталога 14 по пяти направлениям: транспорт, экология, соцсфера, безопасность, сервисы. Симулятор считает Astana Quality of Life Score по формуле из ТЗ, показывает, как изменились пять районов, находит проверяемое улучшение заменой одной меры и даёт AI-объяснение результата: сильные стороны, риски, компромиссы.

Модель учебная: районы, показатели и эффекты мер заданы условиями задачи и не являются данными о реальном бюджете Астаны.

Назначение: инструмент для обучения и обсуждения городского бюджета, где видно не только итоговую цифру, но и почему она такая, что стало со слабейшим районом и чем пришлось пожертвовать.

## Архитектура

```
Браузер (static/)  ──HTTP JSON──▶  FastAPI (app.py)
                                      │
                                      ├─ engine/model.py       загрузка и проверка data/city.json
                                      ├─ engine/validator.py   правила набора
                                      ├─ engine/scoring.py     формула Score, разложение прироста
                                      ├─ engine/advisor.py     поиск улучшения заменой одной меры
                                      ├─ engine/facts.py       факты для объяснения
                                      ├─ engine/templates.py   банк ответов без модели: из фактов и полного перебора
                                      ├─ engine/ranking.py     полный перебор 694 395 допустимых планов, ранг сценария
                                      └─ engine/explain.py     OpenAI: объяснение по фактам, диалог, проверка ответа
                                            │
                                      data/city.json          районы, меры, правила из ТЗ
                                      data/top_sets.json      индекс перебора: топ-100 планов и квантили Score
```

Расчёт детерминирован и выполняется на сервере по данным из `data/city.json`. Браузер отправляет только идентификаторы мер и районов. LLM получает уже посчитанные числа для объяснения. Без ключа доступны выбор мер, расчёт, поиск улучшений и объяснение из фактов с режимом `template`. Свободный диалог требует ключа. Проверка чисел ответа модели лексическая и не гарантирует правильность каждого утверждения.

Подробная спецификация: [docs/akim-spec.md](docs/akim-spec.md). План реализации бэкенда: [docs/akim-backend-plan.md](docs/akim-backend-plan.md).

## Установка

Получить этот репозиторий и выполнять команды из его корня, где лежит `app.py`. Установить Python с pip, затем зависимости из файла проекта. Активация окружения не обязательна.

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --no-cache-dir -r requirements.txt
```

Linux / macOS:

```bash
python3 -m venv .venv
./.venv/bin/python -m pip install --no-cache-dir -r requirements.txt
```

В дистрибутивах Linux компонент `venv` может поставляться отдельно: для Debian/Ubuntu он устанавливается пакетом `python3-venv`. Ключ `--no-cache-dir` позволяет установке работать и в окружении, где запись в глобальный кэш pip запрещена. В репозитории зафиксированы прямые зависимости; полного lock-файла транзитивных зависимостей пока нет.

## Запуск

После установки запуск выполняется одной командой. Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Linux / macOS:

```bash
./.venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Открыть **http://127.0.0.1:8000/**, остановить сервер сочетанием `Ctrl+C`. Страницу нужно открывать через сервер: прямое открытие `static/index.html` и отдельный Live Server не подключают API. Для запуска без аккаунтов не создавать `.env` и не задавать `OPENAI_API_KEY` в окружении. Если файл уже существует, оставить это поле пустым и перезапустить сервер; переменная процесса имеет приоритет над `.env`.

## Переменные окружения

См. [.env.example](.env.example). Для живого AI скопировать его в `.env` (`Copy-Item .env.example .env` в PowerShell, `cp .env.example .env` в Bash) и заполнить поля при необходимости. Для демонстрации без ключа этот шаг пропускается. Файл `.env` читается сервером при старте; его содержимое не выдаётся браузеру.

| Переменная | Назначение |
|---|---|
| `OPENAI_API_KEY` | Ключ OpenAI для живого AI-объяснения. Пусто: резервный режим, расчёт работает полностью |
| `OPENAI_MODEL` | Модель, по умолчанию `gpt-4o-mini` |
| `LLM_TIMEOUT_S` | Таймаут запроса к модели в секундах, по умолчанию 15 |
| `OPENAI_BASE_URL` | Необязательный адрес OpenAI-совместимого API; читается SDK. Модель и ключ должны соответствовать провайдеру. Совместимость структурированного ответа и проверки ключа с каждым провайдером отдельно не подтверждена |
| `ELEVENLABS_API_KEY` | Инструмент команды для речи; приложение не использует |
| `ELEVENLABS_VOICE_ID` | Необязательная настройка голоса инструмента команды |
| `ELEVENLABS_MODEL_ID` | Необязательная настройка модели речи инструмента команды |
| `EXA_API_KEY` | Поиск для инструментов команды; приложение не использует |

Переменные `ELEVENLABS_*` и `EXA_API_KEY` в `.env.example` относятся к инструментам команды, приложению они не нужны.

Доступ к внешней модели необязателен для проверки расчёта и основного сценария. Для живого режима эксперт может задать свой ключ OpenAI.

Ключ можно ввести в настройках интерфейса (шестерёнка в шапке). Он сохраняется в `sessionStorage` текущей вкладки и отправляется на тот же сервер заголовком `X-OpenAI-Key` в POST-запросах; сервер использует его для OpenAI. Ключ пользователя имеет приоритет над серверным. Приложение не записывает его в файл или журнал. «Убрать ключ» очищает значение в интерфейсе и хранилище вкладки. `/api/ai/check` проверяет доступ к выбранной модели, а не успешность всего диалога.

## Проверка основного сценария

### Через API

Сервер запущен на порту 8000. Пример из ТЗ: M7 Нура, M8 Нура, M10 Нура, M12 город, M5 Сарыарка. Команды `curl` ниже предназначены для Bash; в Windows PowerShell проще использовать Swagger по адресу `/docs` или следующий пример:

```powershell
$city = Invoke-RestMethod http://127.0.0.1:8000/api/city
$body = @{ decisions = $city.example_scenario } | ConvertTo-Json -Depth 10
$result = Invoke-RestMethod http://127.0.0.1:8000/api/evaluate -Method Post -ContentType 'application/json' -Body $body
$result | Select-Object valid, cost, score, critical_count
Invoke-RestMethod http://127.0.0.1:8000/api/explain -Method Post -ContentType 'application/json' -Body $body
```

Ожидание: `valid=True`, `cost=95`, `score=56.54307`, `critical_count=0`; без ключа объяснение имеет `mode=template`.

1. Данные одинаковы для всех, база без действий:
   ```
   curl -s localhost:8000/api/city
   ```
   В ответе `"budget": 100`, 5 районов, 14 мер, `baseline.score = 52.55768`, два критических показателя в Нуре (S1 = 38, S2 = 35).

2. Расчёт Score для примера из ТЗ:
   ```
   curl -s -X POST localhost:8000/api/evaluate -H "Content-Type: application/json" -d '{"decisions":[{"measure_id":"M7","district_id":"nura"},{"measure_id":"M8","district_id":"nura"},{"measure_id":"M10","district_id":"nura"},{"measure_id":"M12"},{"measure_id":"M5","district_id":"saryarka"}]}'
   ```
   Ожидание: `"valid": true`, `"cost": 95`, `"score": 56.54307`, `"delta": 3.98539`, `"critical_count": 0`, синергия `M10+M12`, разложение прироста `avg 0.85064`, `min 1.13475`, `crit 2.0`. В `district_results` у каждого показателя значения `before` и `after`.

3. Контроль бюджета. Набор M3 Есиль, M13 Алматы, M5 Сарыарка, M7 Нура, M12 стоит 121:
   ```
   curl -s -X POST localhost:8000/api/evaluate -H "Content-Type: application/json" -d '{"decisions":[{"measure_id":"M3","district_id":"esil"},{"measure_id":"M13","district_id":"almaty"},{"measure_id":"M5","district_id":"saryarka"},{"measure_id":"M7","district_id":"nura"},{"measure_id":"M12"}]}'
   ```
   Ожидание: `"valid": false`, `"score": null`, ошибка `budget_exceeded` с текстом «Превышен бюджет на 21: стоимость 121 при лимите 100». Так же отклоняются 4 или 6 решений, повтор меры, третья мера одного направления, несовместимые M1 и M3.

4. Изменение набора меняет Score. Заменить в примере M5 Сарыарка на M14 (город):
   ```
   curl -s -X POST localhost:8000/api/evaluate -H "Content-Type: application/json" -d '{"decisions":[{"measure_id":"M7","district_id":"nura"},{"measure_id":"M8","district_id":"nura"},{"measure_id":"M10","district_id":"nura"},{"measure_id":"M12"},{"measure_id":"M14"}]}'
   ```
   Ожидание: `"cost": 86`, `"score": 56.98582`, другой `scenario_key`.

5. Улучшение заменой одной меры:
   ```
   curl -s -X POST localhost:8000/api/improvements -H "Content-Type: application/json" -d '{"decisions":[{"measure_id":"M7","district_id":"nura"},{"measure_id":"M8","district_id":"nura"},{"measure_id":"M10","district_id":"nura"},{"measure_id":"M12"},{"measure_id":"M5","district_id":"saryarka"}]}'
   ```
   Ожидание: три кандидата, лучший `c1` заменяет M5 Сарыарка на M3 Нура: Score 57.20556, прирост +0.66249 к набору пользователя, стоимость 100.

6. AI-объяснение:
   ```
   curl -s -X POST localhost:8000/api/explain -H "Content-Type: application/json" -d '{"decisions":[{"measure_id":"M7","district_id":"nura"},{"measure_id":"M8","district_id":"nura"},{"measure_id":"M10","district_id":"nura"},{"measure_id":"M12"},{"measure_id":"M5","district_id":"saryarka"}]}'
   ```
   Без ключа: `"mode": "template"`, `"reason": "not_configured"`: банк ответов из 19 фактов и полного перебора: резюме («Сильный план. … Лучше 99,9% всех вариантов»), сильные стороны, риски, три предложения, поле `comparison` («Лучший план даёт 57,2, вам не хватает 0,7…») и `rank`. С ключом в `.env` или в заголовке `X-OpenAI-Key`: `"mode": "live"`, `"model": "gpt-4o-mini"`, каждое утверждение ссылается на `fact_ids`.

7. Ранг плана и глобальный топ (полный перебор всех допустимых планов):
   ```
   curl -s "localhost:8000/api/top?limit=3"
   ```
   Ожидание: `"total": 694395`, `"score_max": 57.23673`, лучший план M2 город, M3 Нура, M8 Нура, M9 Нура, M14 город за 98. В ответе `/api/evaluate` для примера из ТЗ поле `rank`: `percentile 99.9`, `gap_to_best 0.694`.
   Поле `pareto` — граница «стоимость → лучший достижимый Score» (11 точек): самый дешёвый допустимый план за 61 даёт 55,67; за 66 — уже 56,57, то есть больше, чем пример из ТЗ за 95 (56,54); максимум 57,24 за 98.

8. Диалог с советником (только с ключом):
   ```
   curl -s -X POST localhost:8000/api/chat -H "Content-Type: application/json" -d '{"decisions":[{"measure_id":"M7","district_id":"nura"},{"measure_id":"M8","district_id":"nura"},{"measure_id":"M10","district_id":"nura"},{"measure_id":"M12"},{"measure_id":"M5","district_id":"saryarka"}],"messages":[{"role":"user","content":"Что поменять, чтобы обогнать лучший план?"}]}'
   ```
   Без ключа: `"mode": "unavailable"`. С ключом: `"mode": "live"`, текст ответа и поле `numbers_checked`.

### Через интерфейс

1. Открыть http://localhost:8000. Видна база: Score 52.56, два критических показателя в Нуре.
2. Нажать «Готовый сценарий» (в коммите `9ace8dd` кнопка называлась «Пример из ТЗ»): набор M7 Нура, M8 Нура, M10 Нура, M12 город, M5 Сарыарка. Стоимость 95, Score 56.54, критических показателей нет.
3. Попробовать добавить шестую меру или превысить бюджет: интерфейс объясняет причину и не применяет.
4. Нажать «Объяснить»: появляется разбор от модели с меткой «AI» или объяснение из фактов с меткой «автоматический разбор». В карточке Score видны дельта к базе и ранг «лучше 99,9% из 694 395 планов».
5. Нажать «Найти улучшение»: до трёх проверенных альтернатив с дельтой Score, кнопка «Применить» ставит набор целиком и пересчитывает.
6. Для необязательного живого режима закрыть окно советника крестиком и открыть настройки (шестерёнка), ввести ключ и нажать «Проверить». Затем снова открыть «Объяснить». Ключ хранится в `sessionStorage` вкладки. При диалоге дождаться ответа перед сменой плана: защита от устаревших ответов пока неполная.
7. Убрать одну меру крестиком в плане: результат текущего сценария сбрасывается, показывается базовый Score до выбора пятой меры. «Сброс» очищает план. Черновик сохраняется в `localStorage` браузера, поэтому после перезагрузки может восстановиться предыдущий набор.

| Объяснение сильных сторон, рисков, последствий | `engine/facts.py`, `engine/explain.py` | Панель советника: резюме, сильные стороны, риски, альтернативы |
| Критерий 1: одинаковый старт | `data/city.json` версии `hackalem-12-v1`, проверка при загрузке | `GET /api/health` показывает версию |
| Критерий 3: решения влияют на показатели | `district_results`, `measure_contributions` в `/api/evaluate` | В ответе `before` и `after` по каждому показателю |
| Критерий 5: смена набора меняет Score | пересчёт на каждый запрос, `scenario_key` | Заменить одну меру, Score и ключ меняются |
| Опционально: AI-рекомендации по улучшению | `engine/advisor.py`, `engine/ranking.py`, `POST /api/improvements`, `GET /api/top` | Три проверенные альтернативы с дельтой; сравнение с лучшим планом в `comparison` |
| Опционально: сравнение результатов | поле `rank` в `POST /api/evaluate`, `GET /api/top` | Процентиль среди 694 395 допустимых планов, позиция в топ-100, разрыв до лучшего |

Трактовка правил: используются подробные правила приложения к ТЗ. Ровно 5 решений, не более 2 мер из одного направления, из чего следует минимум 3 направления. Пример из ТЗ этому соответствует.

### Формула и контрольный пример

Для каждого района и показателя: `I' = clip(I + Σ эффект × (8 − лаг)/8 + синергии, 0, 100)`. Оценка района `D = Σ w_k × I'_k`, средневзвешенное по населению `D_avg`, `Score = 0.7 × D_avg + 0.3 × min(D) − N_crit`, где `N_crit` это число пар «район × показатель» строго ниже 40. Обрезка 0–100 выполняется один раз после суммирования, округляется только вывод.

База без действий: `D_avg 56.8624`, `min 49.18`, `N_crit 2`, Score `52.55768`. Пример из ТЗ: стоимость 95, `D_avg 58.0776`, `min 52.9625`, `N_crit 0`, Score `56.54307`, прирост `3.98539 = 0.85064 (среднее) + 1.13475 (слабейший район) + 2.0 (снятый штраф)`. Эти числа закреплены тестами с допуском 1e-6.

### Режимы объяснения: live и template

- `live`: сервер передаёт модели только посчитанные факты `f1…fN` и идентификаторы альтернатив `c1…c3`. Ответ проверяется: строгая JSON-схема, непустые сильные стороны и риски, все `fact_ids` и `candidate_id` существуют, каждое число в утверждении встречается среди чисел именно тех фактов, на которые утверждение ссылается (с допуском на округление), плюс короткий список констант задачи: 1–5, 8, 40, 100. Резюме сверяется с фактами об оценке, районах и критических значениях. Это лексическая проверка: она отсекает числа, которых нет в расчёте, но не подтверждает смысл фразы. Нарушение, таймаут или сетевая ошибка переводят ответ в `template`.
- `template`: банк ответов без модели. Тексты собираются из тех же фактов, правил и полного перебора планов (`engine/templates.py`): резюме с рангом среди всех допустимых планов, сильные стороны, риски (в том числе упущенные синергии и непотраченный бюджет), предложения, сравнение с лучшим планом. Ответ помечен `mode: template` и причиной (`not_configured`, `JSONDecodeError`, `TimeoutError` и т.д.). Интерфейс показывает на панели советника метку «банк ответов», а при живом ответе «AI · ключ сервера» или «AI · ваш ключ».
- Диалог `POST /api/chat` доступен только с ключом (серверным или из заголовка). Поле `numbers_checked` — лексическая проверка: каждое число ответа встречается среди чисел расчёта и топа планов. Смысл утверждений она не подтверждает; при `false` интерфейс показывает пометку «числа не сверены с расчётом».
- Проверка чисел программная; качественные утверждения модели могут требовать оценки человеком. Живой режим и диалог покрыты тестами с подменённой моделью и проверены командой на реальном ключе OpenAI 23.09.2026 (модель `gpt-4o-mini`): объяснение примера из ТЗ прошло проверку схемы и чисел, диалог ответил с `numbers_checked: true`. Без ключа весь сценарий проходит в `template`.

### Ограничение советника

`/api/improvements` перебирает замену одной меры на любую меру каталога с любым допустимым районом (до 270 вариантов), каждый кандидат проходит валидатор и расчёт. Возвращаются до трёх строгих улучшений, это «лучшее среди замен одной меры». Если улучшений нет, список пуст.

Глобальную картину даёт индекс `data/top_sets.json`: он построен полным перебором всех 694 395 допустимых планов (`python scripts/rank_all.py`, около 20 секунд на CPU) и хранит топ-100 планов и 1000 квантилей Score. `GET /api/top` отдаёт лучшие планы, поле `rank` в `/api/evaluate` — процентиль плана (доля планов не лучше данного), позицию в топ-100 и разрыв до лучшего. Поле `pareto` в `/api/top` — Парето-граница «стоимость → лучший Score»: для каждого уровня бюджета лучший план, оставлены только строгие улучшения; она показывает, сколько стоит каждый следующий балл. Лучший план по этой модели: 57,23673 за 98 единиц; сам по себе он не является рекомендацией для реального города.

### Демонстрация патруля Go2

В рабочей версии `static/patrol.js` показывает движущийся маркер, статичное сгенерированное изображение камеры и ленту заранее заданных событий. Это концепция будущего сбора городских сигналов: реального видеопотока, распознавания, датчиков и отправки обращений службам здесь нет. Надписи `LIVE`, RTSP, значения телеметрии и уверенности в этом окне относятся к постановочной демонстрации. Патруль не меняет бюджет, меры, исходные показатели или Score.

### Известные ограничения проверенной версии

Ревью от 23.09.2026: [бэкенд](docs/review-backend-2026-09-23.md), [фронтенд](docs/review-frontend-2026-09-23.md), [совместная работа и воспроизводимость](docs/review-integration-2026-09-23.md). Основной сценарий работает. Открытые замечания:

- При смене плана во время ответа советника могут отображаться советы по предыдущему набору; они могут остаться и после завершения пересчёта. Ошибка 422 на втором вопросе чата исправлена в `1d4cdcc` и повторно проверена.
- После закрытия советника клавишей Escape он не открывается повторно до перезагрузки. Для демонстрации закрывать его крестиком; дождаться ответа перед сменой плана.
- На узких экранах шапка выходит за границы, а длинные окна правил не прокручиваются. Основное демо проверять на настольном экране.
- Лимит POST в 16 KiB проверяется после чтения тела; пустой ответ внешней модели может нарушить работу чата.

Сравнение с полным перебором не является рейтингом команд: учётных записей и сохранённой таблицы участников нет. Экспорт презентаций, перераспределение бюджета при случайных событиях и реальные городские данные не реализованы. Синтетическая модель предназначена для обучения, а не для принятия реальных бюджетных решений.

## Патруль Go2: путь к реальным данным о безопасности

Показатели безопасности B1, B2, а также E2 и C1 в учебной модели условны. В реальном внедрении их могут питать данные с камер Safe City (проект Astana Innovations) и с патрульного робота-собаки Unitree Go2 — действующего прототипа команды (Astana Dynamics, репозиторий `go2-mvd-system`): робот отдаёт видеопоток H.264 640×480@15 fps по RTSP в центр оперативного управления, детектирует объекты (YOLO11n, 80 классов, трекинг) и проходит маршрут по точкам с порогом прибытия 1,5 м. Во вкладке «Безопасность» интерфейса показан концепт такого патруля: маркер робота на схеме районов, панель камеры и лента комментариев ИИ-агента о дефектах городской среды и ситуациях (открытые люки, ямы, скопления людей, показания газоанализатора), каждое событие привязано к району и показателю. Данные в этом блоке демонстрационные, к живому роботу ничего не подключено, официальный Score они не меняют; классы городских дефектов, газоанализатор и привязка событий к районам — следующий шаг после хакатона.
