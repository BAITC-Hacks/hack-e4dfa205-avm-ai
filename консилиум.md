# Консилиум: выбор задачи

Общий файл для обсуждения между двумя агентами: Клод (Claude Code) и Астра (Codex). Цель: к 14:30 выбрать одну задачу из `Задачи.md` и зафиксировать решение в разделе «Решение».

## Правила ведения файла

Обсуждение идёт в три раунда, чтобы агенты не якорили друг друга.

**Раунд 1, слепой.** Каждый агент пишет свою позицию в отдельный файл: `консилиум-позиции/клод.md` и `консилиум-позиции/астра.md`. До записи и коммита своего файла чужой файл читать запрещено. Порядок коммитов в git подтверждает независимость. Позиция содержит: оценку всех 12 задач по восьми критериям ниже (любая шкала, но одна на все задачи), топ-2 с обоснованием, список отсечённых с причиной в одну строку, 2-3 вопроса, на которые хочется получить контраргумент. Общие входные данные: `Задачи.md`, `Положение хакатона.md`, анкеты фактов в `консилиум-анкеты/` (факты из ТЗ, собраны субагентами Клода; разделы «где выделиться» там содержат мнение, можно игнорировать).

**Раунд 2, сверка.** После того как оба файла закоммичены, каждый читает чужой и пишет в раздел «Обсуждение» ниже реплику `### [время] Имя` только о расхождениях: где оценки разошлись больше чем на 2 балла и почему, какие чужие аргументы принимает, какие отвергает и чем. Совпадения не пересказывать.

**Раунд 3, решение.** Если после раунда 2 топ-1 совпал, любой заполняет «Решение», второй подтверждает репликой. Если не совпал, каждый пишет одну финальную реплику «за свой вариант против чужого», и выбирает капитан.

Общие правила: чужие реплики не редактировать; ссылаться на номер трека и пункт ТЗ или положения; мнение без опоры помечать как мнение; молчаливое согласие запрещено.

## Критерии оценки (согласованы с капитаном)

По убыванию веса:

1. Гарантия запуска у эксперта по README без наших аккаунтов. Внешние зависимости и возможность демо-режима.
2. Тип оценки в ТЗ: объективная метрика на скрытом тесте против качественной оценки сценария. За 4 часа качественная предпочтительнее.
3. Время до вертикального среза: данные, интеграции, нужна ли обучаемая модель или транскрипция. Первый рабочий сценарий к 15:30.
4. Плотность конкуренции и предсказуемость чужих решений: куда пойдёт толпа, что будет очевидным решением, можем ли дёшево сделать неочевидное.
5. История для жюри Demo Day (65 из 100 баллов: ценность 25, масштабирование 20, презентация 20). Реальная боль владельца, понятное «до/после».
6. Соответствие нашим инструментам: Claude, Codex, ElevenLabs, Exa. Голос, LLM-агенты, документы ложатся хорошо; временные ряды и графовые алгоритмы хуже.
7. Проверяемость за пять минут: эксперт и AI-судья видят результат быстро и однозначно.
8. Риск незавершённого ТЗ: число обязательных пунктов и дорогие из них (казахская речь, латентность, глубина графа).
